1. Elección de la Aplicación Web

Para el desarrollo de este reto, se optó por crear un sistema de gestión para la "Farmacia Cristo Médico". El propósito principal de esta aplicación es digitalizar y optimizar el control de inventario (almacén), el registro de nuevos medicamentos y el proceso de punto de venta.

La necesidad que busca resolver es la eliminación de los registros manuales en papel, los cuales suelen ser propensos a errores, pérdida de información y falta de actualización en tiempo real sobre el stock disponible. La razón que motivó esta selección fue que el sector farmacéutico requiere de un control estricto y rápido; además, la estructura del sistema permite aplicar de manera práctica los conceptos de organización de archivos estáticos (HTML, CSS, JS), los cuales son ideales para el proceso de empaquetado y despliegue solicitado en este reto.

2. Desarrollo

¿Cómo realizaste el empaquetado?

Primero, se organizó la estructura del proyecto creando carpetas específicas para los recursos (/css para los estilos, /js para la lógica de la aplicación, y /img para las imágenes). Posteriormente, se utilizó una herramienta en línea (MinifyCode) para minificar los archivos styles.css y app.js, reduciendo su peso al eliminar espacios en blanco y saltos de línea innecesarios. Finalmente, se seleccionó la carpeta principal y se comprimió en un archivo .zip, dejándolo listo para el servidor.

Figura 1. Organización de carpetas y minificación de archivos CSS/JS.

¿Cómo gestionaste el versionamiento?

Se creó un repositorio público en GitHub llamado "Farmacia-Cristo-Medico". Utilizando Git en la terminal, se inicializó el repositorio (git init), se agregaron los archivos (git add .) y se realizaron múltiples commits descriptivos, por ejemplo: "feat: estructura inicial de carpetas", "style: minificación de CSS" y "docs: actualización de README". Finalmente se subió todo al repositorio remoto con git push origin main.

Figura 2. Historial de commits en el repositorio de GitHub.

¿Cómo configuraste el servidor?

Se optó por utilizar el servidor web Apache mediante la suite XAMPP en un entorno local (simulación). Se descomprimió el archivo .zip dentro de la carpeta htdocs (mapeo de directorios). Posteriormente, se editó el archivo httpd-vhosts.conf para crear un Virtual Host, asignándole el puerto 80 por defecto y apuntando el DocumentRoot a la carpeta de la farmacia. Finalmente, se accedió a través de la ruta simulada http://localhost/farmacia_cristo_medico.

Figura 3. Configuración del Virtual Host en Apache y prueba en navegador local.

3. Conclusión

Durante la realización de este reto, el principal desafío fue la correcta configuración del servidor Apache y el mapeo de directorios, ya que al principio la ruta de localhost arrojaba errores 403 (Prohibido) o 404 (No encontrado). Este problema se resolvió verificando cuidadosamente la sintaxis del archivo httpd-vhosts.conf y asegurando que los permisos de la carpeta en htdocs estuvieran correctamente asignados. Otro reto menor fue el empaquetado y la minificación, pues al minificar el código JavaScript es fácil borrar accidentalmente alguna sintaxis necesaria (como un punto y coma), lo cual rompía la aplicación; esto se solucionó probando el código minificado localmente antes de comprimir el archivo final. En general, fue una práctica muy enriquecedora que conecta el desarrollo frontend con las tareas de despliegue en producción.
